# Exhaustive implementation plan for the open protocol checks

| Product | Exact positive owner and quantification | Negative controls | Boundary |
|---|---|---|---|
| Hostile work | Actual prepared N3 ledger, selected acquisition and evidence jobs from capture through reporting, bounded junk identifiers, duplicate admissions, job retry and preserved work across one outage. Explore arrival and effect order in the selected relation. | Shared work consumes slot, priority inversion and lost ready job; safety with no service under otherwise admissible actions. | Bounds measured from eligible service after recovery. Physical latency and arbitrary arrival rate are separate. |
| Clock and inclusion | Distinguish elapsed time, ledger height, independent block rate, B offset/drift, monotonic source inclusion, replacement and confirmation. Compose the actual deadline/hold path in direction tests. | Early issue, stale inclusion replacement, local B expiry, stalled A and missing service. | Confirmation is a named abstraction; the selected rate and drift domains are recorded. |
| Changing authority | Check cross-round signature locks, different memberships with predecessor authorization, immutable history and accepted executed statements; include a model of accumulating key exposure. | Reset lock, incompatible predecessor, unadmitted/stale key/context, incompatible restored checkpoint, mobile corruption with retained old keys. | Signed logical authority, with explicit corruption and view-change assumptions. |
| Placement | Source-bound B, D, shared profiles using actual signed N3 transition actions, local and remote leg requirements, immutable issues and independent report proof. | Missing local effect, wrong terminal fact/phase, lost/duplicate delivery, premature both-leg record. | Finite selected scenarios with preserved source actor semantics and placement-specific state. |
| Contract history | Observe invocation, inclusion, finalization, actual contract effect, retry and response across logical A/B; use legal local projection and durable rows checked against the independently observed source. | Reply before effect, half effect or duplicate outcome, stale restored state, wrong authenticated response and stale worker replay. | Logical contracts; real production infrastructure is outside the user-approved iteration. |
| Privacy | Two differing private worlds evaluated separately on the same public schedule. Status, batches, proof metadata, backup cache, outages, scopes, role change and key usability each have an observable or allowed declassification. | Routing, timing, backup size/address hints, stale authorization and unavailable key/note. | Exact finite paired trace envelopes and ideal secret/opaque scope. |
| Unbounded safety | Arbitrary population and arbitrary affected/untouched indices, nonnegative capacity and exact state projection. Check initiation, closed local transition obligations and counterexamples by solver. Check actual operation correspondence independently. | Aliased roots, double consumption, a missing capacity guard and unapproved authority. | State explicitly which formulas are population-independent and which future compositions still use finite tests. |

An expected counterexample supplies a discriminator. A syntax error, timeout, blocked precondition or fault outside a theorem's declared envelope does not supply a green result. All new executable inputs are captured by the existing receipt scheme. The old 316 acceptance selections retain their exact meanings. The [new evidence record](../../../verification/reports/proof-products.md) links each plan row to checker bounds, counterexamples and source correspondence.
