## Findings

### VGR-01 — High for assurance: matching outcome on B is implicit in the writer of local knowledge

[S06](../../models/dvp.qnt#L360) checks cash delivery against local `knownB == 2`. The [learn transition](../../models/dvp.qnt#L223) sets this value from the appropriate verified terminal fact. The oracle lacks an independent assertion that B's learned outcome and cash delivery agree with the authoritative result.

- **Witness.** Both parties sign, only B prepares, and A reaches its deadline and records the ABORT tombstone. The genuine phase-4 outcome is finalized, captured, proved and delivered. The original `learn(1,2,1)` rejects it as COMMIT. A copy with one outcome-to-phase selection error lets B learn COMMIT from that same ABORT proof. `applyB` then delivers the cash while A's decision stays ABORT and A has no hold. `safe` and `CDecision` both pass at that state. The independent `cashAuthorized` predicate fails. Absence of a mixed delivery and refund is insufficient when the other leg never existed.
- **Fix criterion.** Assert outcome/evidence consistency separately from the transition that sets local knowledge. Require the proper remote outcome evidence and a matching authoritative decision for remotely applied legs. For a co-located leg, check the decision and the economic effect in the same transition. The assertion can inspect the combined model state. A distributed production consumer sees local state and authenticated inputs. Retain the original rejection and the wrong-phase control.
- **Evidence.** [Original guard](evidence/outcome-control.log) · [Isolated wrong-phase witness](evidence/outcome-wrong-phase.log) · [Independent review predicate](monitors.qnt).

### VGR-02 — High for assurance: COMMIT reconciliation trusts application flags as its own witness

The [observer and reconcile actions](../../models/dvp.qnt#L265) set and consume cached flags. The COMMIT branch of [S15](../../models/dvp.qnt#L380) reads those same flags to justify `report == 2`. The ABORT branch independently checks actual release or terminal absence. S05 checks the terms and outcome of the exact financial row, so a correctly populated but premature row can still pass it.

- **Witness.** Security is delivered, cash remains held, and the reporter has authentic phase-5 application evidence from A. The original observer rejects phase-6 application without corresponding B evidence. Removing that check for B in an isolated copy lets the reporter set B's flag, mark FULLY_APPLIED and book the exact trade while cash remains undelivered. `safe` and `CDecision` pass and `commitRecordSound` fails.
- **Fix criterion.** Require actual effects on both legs plus both bound application facts whenever COMMIT is reported or a COMMIT financial row exists. Check the financial row independently of the volatile report, which can be reset by restart. Derive the externally emitted stage from evidence-backed records. Cached fields can accelerate lookup once their relationship to those records is checked. Revalidate the L04 endpoint as well as S15.
- **Evidence.** [Original guard](evidence/report-control.log) · [Isolated premature report witness](evidence/report-missing-evidence.log) · [Independent review predicate](monitors.qnt).

Both review assertions passed TLC on the original one-trade native A profile with its actual `init` and normal `step`. That run covered **12,502 reachable states at depth 38**. Its arguments select the two new assertions. The directed tests use unchanged core assertions as part of the fault discriminator. Two trades, recovery and other placements require their own observations for the strengthened assertions. ## A simpler design and a shorter path to stronger evidence

1. **Keep the PoC kernel small.** One decision placement, one supported token behavior per leg, durable holds, an exclusive A-height deadline, tombstones and two types of remote fact on the settlement path: B preparation and A outcome. Application evidence goes to reporting separately. Keep B/D/shared, escrow and private assets as profiles for their respective requirements. Use the complete signed descriptor on every path. Add an OPEN round trip or a generic call tree only when required.
2. **Keep decision, application and reporting distinct.** Store the terminal decision, the two local application results and reconciliation evidence. Expose authorization, registered/reserved, backed COMMIT, local applications and booked completion as distinct facts. Use stable operation IDs for idempotent submit/apply/book actions. Recovery consumes the same authenticated results as the normal run. A restored snapshot is a projection to reconcile and cannot authorize value movement.
3. **Close VGR-01 and VGR-02 first.** Use the independent predicates and keep both discriminators as regressions. Extend to A/B/D/shared using the placement and leg table. Tie L04 to the independent booking predicate. Check affected assertions with the same transition relation in the reference, two-trade and named recovery configurations. Preserve false-init/step controls for any new induction.
4. **Connect governance and reporting to an executable boundary.** Exercise rotation/exit plus pending payment/bookkeeping, stale projection restore plus replay, and freeze after COMMIT. Compare both authoritative ledgers and actual database rows to a model oracle. Demonstrate the real proof verifier, atomic rollback, and retained evidence on two networks before broadening supported asset semantics.
5. **Measure the implementation.** Compare placement, proof batching and gating by time to both applications, maximum observed age of active holds and time to reconciliation. The slot model gives bounds only for its finite workload.

The remaining material design decision is the meaning of atomicity. With independent native ledgers, require C-Decision plus conditional C-Local and evidence-backed C-Records. If the contract forbids the one-sided local-use interval, evaluate shared execution or a separately enforced usability gate. An added gate changes usable ownership and needs its own access, recovery and legal analysis.

## Reproduction

Run the four directed cases to a new directory.

    python3 -B verification/reviews/guarantee-assurance/probe.py verification/results/runtime/guarantee-review-replay

The probe reconstructs model copies from the reviewed commit. It records inputs, invocation and raw output digests in [the results](evidence/results.json). Each mutant case explicitly checks that the bad state satisfies existing assertions and violates a stricter predicate. A regression in the original guard makes the matching control fail. The standalone TLC receipt contains the new assertion check's command and source closure. Earlier checks retain their recorded status.
