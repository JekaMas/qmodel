# Executed cross-chain DvP investigation

The canonical task is ../openspec/changes/verify-cross-chain-dvp/tasks.md. The verification authority is sources/task-v2.md; the versioned source answer is sources/shared-solution.original-ru.md. This project investigates the candidate rather than presuming it correct.

Install the pinned local dependency with `npm ci`. Java 21+ is required by Apalache 0.62.4. The runner uses an existing GoLand Java 25 runtime on this machine; set `QMODEL_JAVA_BIN=/path/to/jdk/bin` on another machine. Quint's cache is project-local `.quint/`; its pinned Apalache download is approximately 200 MB and the Rust evaluator is v0.7.1. No global tool installation or configuration is required.

Run from the repository root:

```sh
python3 verification/scripts/verify.py baseline
python3 verification/scripts/verify.py negative
```

These commands independently audit and reuse the original backend results and exact source snapshots in this repository. They check the final model content inventory and fail on a missing result, corrupted source, tool error, incomplete TLC graph or absent expected counterexample. They do not assert that the historical full-reference timeouts passed. Add `--fresh` only when deliberately requesting new execution against each exact saved input version; selected checks execute sequentially with receipt limits, and the command exits nonzero for an unexpected result. `verify.py audit` checks both result classes. Initial installation is `npm ci`.

For one exact source/seed reproduction: `python3 verification/scripts/replay.py mutant-expiry`. For direct current-tree investigation the older drivers `run_suite.py`, `check_finite.py`, `run_focused.py` and `finish_checks.py` remain available; their broader configurations include deliberately retained resource failures and are not the final acceptance command. Every receipt contains its exact native command. The final matrix has separately named scopes, never a silent fallback from a timeout.

The final [manifest](results/manifest.json), [findings](reports/findings.md), [literal coverage](reports/literal-coverage.md), [contracts](reports/coverage.md), [variants](variants.md), [chronological counterexamples](reports/counterexamples.md) and [conformance boundary](reports/conformance-boundary.md) are the review entry points. Full production-facing interface test vectors are in tests/conformance-vectors.json; no production implementation was present.

Every command is executed through bounded subprocesses with raw output and receipts under results/runs. Heavy checkers run sequentially. Existing valid receipts are retained when the exact command and semantic inputs match; changed models produce new attempts without deleting prior evidence. Counterexample expectations require a recognized invariant/temporal violation, not merely a nonzero exit. ITF traces are generated by the simulator where supported. TLC native textual counterexamples, including temporal cycles, remain in raw logs; this Quint release removes its TLC temporary directory and does not export TLC ITF.

Models are finite abstractions, with one/two distinguishable trade identities, integer quantities 2 security and 3 cash, recipients 1/2, saturating decision height D=2 and bounded source fact phases. Native reservation accounting keeps reserved quantities in owner balances while excluding them from available spending. Escrow accounting moves reserved quantities to a vault. Payout counters are not capped in the transition relation; duplicate-payment mutants can increment them to two.

Each suite has a separate proof boundary. Baseline finite checking does not establish arbitrary-population safety, cryptographic soundness, source QBFT correctness, real EVM/token behavior, deployment availability, legal finality or issuer solvency. The relational privacy result is coupled-public-schedule observational equivalence; timed slot bounds are modeling assumptions rather than measured production latency. See reports/coverage.md and reports/conformance-boundary.md for the final exact limits.
